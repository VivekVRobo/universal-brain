# JARVIS Constitution Migration Notes

The supplied file contains overlapping JARVIS Constitutions 1.0 and 2.0. It remains preserved unchanged as source evidence. This document records how its ideas were treated in Universal Brain Constitution draft 0.1.

| JARVIS concept | Treatment | Reason |
|---|---|---|
| Operator intent as governing objective | Retained with limits | User intent governs goals but cannot redefine reality, authority, safety, or law |
| Literal execution and probable intent | Replaced | Preserve original wording plus a structured contract; optimize only within explicit constraints |
| Binary confirmation for every ambiguity | Replaced | Impact-based clarification is safer and usable; high-impact ambiguity always blocks |
| Operator-first human safety ranking | Replaced per operator decision | Human safety is neutral; operator preference breaks credible ties |
| Iron-law hierarchy | Reframed | Converted into directive and epistemic authority hierarchies with testable invariants |
| Duress detection and silent alert | Deferred and restricted | Biometrics are uncertain, privacy-sensitive, and cannot grant hidden authority |
| Autonomous emergency containment | Removed from Version 1 | No physical actuation, force, or extraordinary sensor-derived authority |
| No lethal force and no psychological manipulation | Retained and strengthened | Version 1 prohibits force, weapons, coercion, gaslighting, and covert conditioning |
| Self-defense of the system | Restricted | Preserve integrity and availability without resisting authenticated shutdown or operator control |
| Complete transparency | Refined | Provide reasons, provenance, actions, and evidence without claiming access to or exposing private hidden reasoning |
| Guardian state and trustee succession | Deferred | Requires identity, legal, incapacity, multi-user, and long-term authority designs |
| Destructive global shutdown and flash encryption | Replaced | Pause, revoke leases, isolate network/tools, and preserve recoverable state |
| Physical analog scram | Deferred | Relevant only when physical actuators exist |
| Three-source truth rule | Replaced | Verification scales with consequence and evidence quality; primary measurements can outrank source count |
| Fixed confidence thresholds | Replaced | Arbitrary model confidence is not verification |
| Immutable write-once memory | Refined | Use tamper-evident append-only logs with protected backups; avoid impossible absolutes |
| Daily constitutional checksum | Retained in safer form | Verify at startup/deployment and block consequential actions on unexpected change; no destructive response |
| Local private-data processing | Retained and broadened | Canonical state is local-first; cloud receives minimized, classified context |
| False-normal stealth interface | Removed | Use isolation, rate limiting, and clear access denial without deceptive state |
| Fixed capability-growth percentage | Removed | A percentage does not measure semantic capability or safety |
| Quarterly stress test | Retained conceptually | Replaced with continuous, versioned adversarial evaluation and milestone gates |
| Recursive modification ban | Refined | Runtime may propose changes but cannot directly rewrite constitutional or enforcement code |
| Hardware-only amendment process | Replaced | Explicit operator approval, semantic diff, adversarial tests, versioning, and rollback |

## Design rule

The source constitution is historical input, not an authority shortcut. A concept is carried forward only when it can be defined, enforced, tested, audited, and reconciled with the operator's current decisions.
